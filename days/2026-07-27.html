Pitch 內容紀錄

問題定義

加密市場資訊環境混亂：Twitter KOL 喊單、新聞標題黨、鏈上鯨魚異動、監管公告散落各處，品質參差不齊。核心困難不是「缺資訊」，而是哪些資訊值得信、哪些是噪音甚至操縱。現有 AI 摘要工具僅拼湊多源內容，不做可信度判斷，不提供證據溯源，不呈現反方觀點——在高風險金融決策場景中不夠用。

核心差異化：Trust Layer（信任提煉層）

在資訊匯聚和 AI 行文之間插入信任提煉層，四大機制：

  1. 逐條評分 — TrustScore = 信譽×0.5 + 交叉佐證×0.25 + 時效性×0.15 − 操縱指標×0.40
  2. 交叉佐證 — 同一 claim 若被多個獨立來源支持則信心上升；互相矛盾則明確標示衝突
  3. 完整溯源 — 每個結論 → claim_id → 原始文件 → source URL/timestamp
  4. 反方證據主動呈現 — 正反兩面都攤出來，不只給支撐方

三層架構

層級職責關鍵模組
Layer 1 — Ingestion多源資料輸入prices / news / social / onchain / hoyabit / regulatory / coingecko
Layer 2 — Trust ★信任提煉（核心）Claim 抽取 → 信譽評估 → 交叉佐證 → 操縱偵測 → 信任加權
Layer 3 — Agent編排 + 溯源生成4步推理：Claim 抽取 → 信任評分 → 帶溯源行文 → 限制複審

技術選型

  • LLM：正式 LLM 呼叫集中經 AWS Bedrock；判斷、評分與證據整合由 TrustForge pipeline 產生
  • 後端：Python 3.11+，零第三方 runtime 依賴（僅 boto3），高可攜性
  • 前端：React + Vite + TypeScript + Tailwind CSS 互動式儀表板
  • 部署：以 AWS App Runner / Lambda 為正式展示部署目標，並保留離線 demo 模式供快速驗證
  • 護欄：內建執行時間與 token 成本控管，15 分鐘內完成全流程

項目格式說明

設計原則（不做的事）

  • 不提供投資建議（HOYA BIT 合規要求）
  • 不硬給結論——資訊完整度優先於結論果斷性
  • 不用第三方現成結論當主要結果——Bedrock 只負責行文，判斷由 pipeline 產生

涵蓋幣種

BTC / ETH / SOL / BNB / XRP（使用 HOYA BIT 提供的企業級 5 年 Daily OHLCV 數據）

Pitch 核心一句話

TrustForge Hermes 把「我看到一堆加密資訊」變成「我知道哪些資訊可信、為什麼可信、證據在哪」——不是又一個摘要工具，而是一個有判斷力、能溯源的分析 Agent。
