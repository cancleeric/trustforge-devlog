2. Peer Metrics 排程器與快取讀寫分離（#587）

完成：新增 peer_metrics_scheduler.py（約 475 行）。寫入路徑（排程）組裝 PeerMetricsSnapshot 寫入快取；請求路徑只讀快取，絕不觸發真實連接器；cache miss 拋 CacheMissError；部分失敗保留上一版並標記 degraded。

價值：把高頻外部依賴從請求關鍵路徑抽離，降低 API 抖動、SSRF、限流影響，是抗抖動的結構性改進。

風險：若排程器當掉而請求路徑靜默拋 CacheMissError，前端會直接缺資料而非降級，比『略舊但可用』更糟。

待驗證：未實跑排程器或模擬 cache miss；degraded 在真實快取後端的 roundtrip 行為未驗證。

3. ImpactPath 評估器：多跳 BFS + 證據綁定，強制「相關而非因果」語言契約（#590）

完成：新增 impact_path_evaluator.py（約 352 行）。以 DependencyEdge 為圖做有界 BFS（深度 ≤3、路徑 ≤20），輸出三態：Evaluated / InsufficientCoverage / NoMatchingEvent；docstring 強制只能用「可能相關」等模糊表述。

價值：把升級事件影響分析從直覺敘事拉到可審計圖遍歷，並把『不得過度宣稱』寫進程式介面層級。

風險：誠實契約靠開發者自律，無靜態檢查擋住未來過度宣稱的結論句；BFS 上限過小可能截斷真實路徑。

待驗證：未跑 test_impact_path_evaluator.py（604 行新增）；語言契約合規性未做端到端文字檢查。

4. Ecolink 升級事件連接器：fail-soft 批次解析（#586）

完成：擴充 ecolink_connector.py，新增 UpgradeEventConnector：以 ConnectorResult(events, errors, skipped_count) 回傳；畸形項目被 skip 記入 errors 而非整批拋錯；依 event_id 去重、過期項先濾再解析。

價值：外部不穩定來源從『一筆壞就全掛』變成『壞的跳過、好的照常』，提升 ingestion 韌性。

風險：fail-soft 溫和吞錯，上游持續吐畸形時 skipped_count 累積但系統表面健康，需下游監控告警才有意義。

待驗證：未執行 test_ecolink_connector.py / test_ecolink_contract.py（共約 500 行新增）；去重與產地欄位真實行為未實跑。

5. 觀測降級標記：全 stale 即 degraded，fail-safe 防誤報 healthy（#537 / #674）

完成：freshness.dashboard() 新增降級判定：全 missing → no_data；全 stale → all_freshness_stale；超過門檻 → stale_exceeds_threshold。核心原則 fail-safe：觀測缺失絕不回報 healthy。

價值：把『無資料≠健康』寫進觀測核心，避免運維在管線斷掉時誤以為正常。

風險：降級門檻若未被呼叫方正確傳入會永不降級；degraded 狀態是否真串到告警/UI 尚未核對。

待驗證：未執行 test_freshness_degraded.py（199 行新增）；前端看板呈現未驗證。

工程意義

本輪整體把 TrustForge 從「能抓資料」推進到「能可信地解釋資料與自身健康度」。三條主線交織：

  • 依賴隔離：peer metrics 的讀寫分離，把外部高頻依賴從請求關鍵路徑徹底抽離，是系統抗抖動的結構性進步。
  • 誠實邊界制度化：ImpactPath 的語言誠實契約、freshness 的 fail-safe 降級，都是把『不誇大、不誤報』從口號變成程式介面與輸出約束——這正是 TrustForge 產品定位的技術化身。
  • 韌性 ingestion：ecolink 的 fail-soft 與 throughput/gas 的 SSRF-safe 邊界，讓外部不穩定來源不再能拖垮整條管線。

但與此同時，CI 被主動關閉、覆蓋率門檻移到本地 gate，意味著『整合驗證』的責任從自動化退回開發者承諾。這是效率與安全網的權衡，需要在下一步被明確補回（見 checklist）。
