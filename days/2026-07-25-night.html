主要變更

  • 前端/後端資產分類契約對齊（#574 / #673）：後端 asset_context.py 的 enum 分類（sector / layer / token_role / market_cap_tier）正式下沉到前端 types.ts——AssetContext 原本是 string 的四個欄位，現在收斂成強型別 union，並保留 unknown 值。關鍵設計決策是：型別層面「不」綁死 enum 白名單（僅提供 isKnownXxx 判斷函式），後端新增 enum 值時前端不會連帶編譯失敗，改由渲染層 fallback。這把「後端認定不明的欄位絕不用空字串冒充」的誠實性原則從文件推進到型別契約。
  • freshness 全 stale 時標記 degraded（#537 / #674）：freshness.dashboard() 新增 degraded / degraded_reason 欄位與一套 fail-safe 判定：當觀測樣本為 0 或全 missing 時標 no_data、全部 stale 時標 all_freshness_stale、部分 stale 超過 degraded_stale_after 門檻時標 stale_exceeds_threshold。同時回傳 last_refresh_epoch、max_stale_age_sec、affected_source_count，讓觀測面板能在「資料全爛」時誠實降級，而不是把空資料誤報成 healthy。
  • replay 回填在 PIT 邊界拒絕無時區時間戳（#515 / #675，CISO ✅）：store_backfilled_source_snapshot() 過去直接用 datetime.fromisoformat 解析 published_at，naive 時間戳會被靜默套用 host-local 時區，造成歷史回填跨越 PIT 邊界的潛在錯誤。現在明確要求 timezone-aware ISO 8601，tzinfo 或 utcoffset 為 None 直接 ValueError 拒絕，並統一 astimezone(utc)。這是 fail-closed 的資料完整性防線，已由 CISO 審核通過。
  • deploy 腳本修復空 SNS 陣列展開（#571 / #672）：put_dedup_alarm.sh 原本在 set -u 下宣告 ALARM_ACTION_ARGS=()，當 SNS_TOPIC 為空時 ${ALARM_ACTION_ARGS[@]} 的展開會因未定義變數觸發 set -u 報錯。改法是不再用陣列，直接在 put_metric_alarm() 裡用 if [[ -n "$SNS_TOPIC" ]] 分支決定是否帶 --alarm-actions/--ok-actions，從根上消除空陣列展開風險。
  • wiki 文件補 Node 版本釘選與強化 pre-push hook（#660/#661/#666）：docs/wiki/pre-push-release-gates.md 補充 Node >= 20.12 的釘選說明與強化後的 pre-push hook 行為，降低本機 frontend / gate 執行時的環境漂移。

工程意義

本輪是「契約收斂 + 誠實降級 + 資料邊界 fail-closed」三條線的同步推進。資產分類從鬆散的 string 收斂成前後端共享的強型別 union，減少跨邊界序列化時的隱性 drift；freshness degraded 標記把「觀測失靈」從靜默 healthy 變成顯式降級，符合 TrustForge 一貫的誠實性立場；replay PIT 的時區拒絕則把歷史回填的資料完整性從「碰巧對」變成「結構上不可錯」。這三者共同把系統往「可解釋、可審計、fail-closed」的信任架構再推一步。

另外，deploy 腳本的修復雖小，卻是把 release gate 在真實 set -u 環境下跑到綠燈的必要前提——很多「本地能過、CI 掛掉」的問題就長這樣。
