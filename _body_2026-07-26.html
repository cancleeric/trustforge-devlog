2. Peer Metrics 排程器與快取讀寫分離（#587）

  • 變更：新增 peer_metrics_scheduler.py（約 475 行）。設計上明確切分為兩條路徑：build_peer_metrics_snapshot() / schedule_peer_metrics_snapshot() 是「唯一會呼叫真實連接器」的寫入路徑，把 TVL+TPS+Gas 三組結果組裝成 PeerMetricsSnapshot 寫入快取；CachedPeerMetricsProvider 則是請求路徑，只讀快取、絕不觸發真實連接器，cache miss 或硬過期時拋出 CacheMissError（與既有 CachedSource 模式一致）。部分失敗時保留上一版快照並標記 degraded，而非整批失效。
  • 風險：讀寫分離的正確性完全依賴排程器的寫入頻率（15 分鐘 cron）與快取硬過期（45 分鐘）設定合理；若排程器當掉而請求路徑靜默拋 CacheMissError，前端會直接看到缺失而非降級資料，反而比『略舊但可用』更糟。
  • 影響：把「高頻外部依賴」從請求關鍵路徑移除，是觀測系統抗抖動的核心架構改進，也讓 SSRF/限流問題被收斂到單一寫入點。
  • 未驗證處：未實際執行排程器或模擬 cache miss；degraded 標記在真實快取後端（非單測 fake）的 roundtrip 行為未驗證。

3. ImpactPath 評估器：多跳 BFS + 證據綁定，且強制「相關而非因果」語言契約（#590）

  • 變更：新增 impact_path_evaluator.py（約 352 行）。以 DependencyEdge 為圖，從事件 asset_id 出發做有界 BFS（最大深度 3、最多 20 條路徑，只走 confidence ≥ 門檻且時間窗活躍的邊），每條路徑綁定支持/反證 Evidence，輸出三態：Evaluated / InsufficientCoverage / NoMatchingEvent。模組 docstring 強制「語言誠實契約」：只能用「可能相關」等模糊表述，禁止把相關表述為因果；並明確規定 InsufficientCoverage 不得被誤讀為「無影響」或「證偽」。
  • 風險：誠實契約是『靠開發者自律』的文字約束，沒有靜態檢查擋住未來有人寫出「證明造成」之類的結論句；BFS 的 max-paths=20 與 depth=3 上限若過小，可能在高連通資產上截斷真實路徑，造成 InsufficientCoverage 被誤判。
  • 影響：這是 TrustForge 把「升級事件影響分析」從直覺敘事拉到可審計圖遍歷的關鍵一步，也把『不得過度宣稱』寫進了程式介面層級，符合產品誠信定位。
  • 未驗證處：未跑 test_impact_path_evaluator.py（604 行新增測試）；語言契約在實際輸出文字上的合規性僅見測試與 docstring，未做端到端文字檢查。

4. Ecolink 升級事件連接器：fail-soft 批次解析（#586）

  • 變更：擴充 ecolink_connector.py，新增 UpgradeEventConnector：以不可變 ConnectorResult(events, errors, skipped_count) 回傳批次解析結果。設計上惡意/畸形項目被 skip 並記入 errors 而非整批拋錯；依 event_id 去重（首筆勝出）；同一 event_id 不同 scheduled_at 取最新；scheduled_at 早於 fetched_at 的過期項目先濾掉再嚴格解析，避免被算成錯誤；每個事件攜帶 observed_at 與 official_source_url 產地資訊。
  • 風險：fail-soft 的代價是『錯誤被溫和吞掉』——若上游持續吐畸形資料，skipped_count 會累積但系統表面健康；需要下游監控告警才有意義，否則靜默退化。
  • 影響：讓官方升級事件這類外部不穩定來源，從『一筆壞就全掛』變成『壞的跳過、好的照常』，提升 ingestion 韌性，也為 ImpactPath 提供乾淨的事件輸入。
  • 未驗證處：未執行 test_ecolink_connector.py / test_ecolink_contract.py（共約 500 行新增）；去重與產地欄位的真實行為未實跑確認。

5. 觀測降級標記：全 stale 即 degraded，且 fail-safe 防誤報 healthy（#537 / #674）

  • 變更：freshness.dashboard() 新增降級判定：當觀測資料缺失（total==0 或全 missing）標記 degraded 且原因 no_data；當全部 stale 標記 all_freshness_stale；部分 stale 但超過門檻則 stale_exceeds_threshold。核心原則是 fail-safe：觀測資料本身缺失時，絕不回報 healthy。
  • 風險：降級門檻（degraded_stale_after）若未由呼叫方正確傳入，會讓部分 stale 場景永遠不降級；另外 degraded 狀態僅在 dashboard 層計算，是否真的串到告警/UI 尚未核對。
  • 影響：把『無資料≠健康』這條安全原則寫進觀測核心，避免運維在資料管線斷掉時誤以為系統正常，是可信賴度（trust）的直接支撐。
  • 未驗證處：未執行 test_freshness_degraded.py（199 行新增）；degraded 狀態在真實前端看板上的呈現未驗證。

工程意義

本輪整體把 TrustForge 從「能抓資料」推進到「能可信地解釋資料與自身健康度」。三條主線交織：

  • 依賴隔離：peer metrics 的讀寫分離，把外部高頻依賴從請求關鍵路徑徹底抽離，是系統抗抖動的結構性進步。
  • 誠實邊界制度化：ImpactPath 的語言誠實契約、freshness 的 fail-safe 降級，都是把『不誇大、不誤報』從口號變成程式介面與輸出約束——這正是 TrustForge 產品定位的技術化身。
  • 韌性 ingestion：ecolink 的 fail-soft 與 throughput/gas 的 SSRF-safe 邊界，讓外部不穩定來源不再能拖垮整條管線。

但與此同時，CI 被主動關閉、覆蓋率門檻移到本地 gate，意味著『整合驗證』的責任從自動化退回開發者承諾。這是效率與安全網的權衡，需要在下一步被明確補回（見 checklist）。
